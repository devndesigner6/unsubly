⚠️ What's NOT AlgoKit Standard
1. No AlgoKit CLI / Framework ⚠️
You're not using AlgoKit (algokit init, algokit build, etc.). AlgoKit is Algorand's official dev framework with project scaffolding, PyTEAL/Beaker/TEALScript compilation, testing, and deployment pipelines
Your TEAL is hand-written raw assembly — which is valid and works, but AlgoKit projects typically use PyTEAL or TEALScript as higher-level languages that compile to TEAL
This isn't a problem — hand-written TEAL is actually more impressive for a hackathon, showing deeper understanding
2. No ARC-4 ABI Methods ⚠️
Despite the memory note mentioning ARC-4, your contracts use raw application args (txn ApplicationArgs 0 compared to byte strings like "release", "kill")
True ARC-4 uses method selectors (first 4 bytes of SHA-512/256 of method signature). Your approach is simpler but functional
This means no contract.json ABI file, no ARC-32 app spec
3. No Local Testing Infrastructure ⚠️
No sandbox or localnet setup — compilation goes directly to testnet's compile endpoint
No unit tests for TEAL contracts
Standard AlgoKit projects include pytest tests with algorand-python-testing
4. Hardcoded Testnet in Edge Function ⚠️
algorand-compile and vault-health edge functions hardcode https://testnet-api.algonode.cloud
When user switches to mainnet in the frontend, compilation and health checks still hit testnet
